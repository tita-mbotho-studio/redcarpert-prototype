# Redcarpert Wedding Dresses

A static bridal catalogue prototype built with **Vite, HTML, CSS and vanilla JavaScript**. The site presents five sample dress categories with twenty illustrative looks, informational pages, fitting-enquiry previews and a downloadable two-page sample lookbook. All photographs are illustrative; they are not confirmed inventory.

## Local development

Requires Node.js 24 (Node >=22.12 is supported by dependencies).

```sh
npm ci
npm run dev
```

Open `http://localhost:5173/redcarpert-prototype/`. Editing document data or adapters requires restarting the dev server to regenerate static HTML.

## Adding page photographs and wedding films

Client-approved and illustrative media URLs are managed in [`src/data/image-links.json`](src/data/image-links.json). The homepage, catalogue and About Us retain their existing images. [Implementation 24](docs/implementation-24-image-links.md) describes the manifest.

## Wedding Moments

Visit **`/wedding-moments/`** to view real client wedding photographs and video in one uninterrupted, responsive square gallery. The page has only the **Wedding Moments** title, the subtitle *“The love, the laughter, the unforgettable moments.”*, and the media grid — no categories or captions. The real client collection currently contains **86 photographs and one directly hosted ImageKit MP4**. The first 16 cards load initially; **Load More** reveals subsequent batches of 16. A live counter below the gallery reads **Showing 16 of 87 wedding moments** and updates to 32, 48, 64, 80 and finally 87.

Client media URLs are stored in `wedding_moments.events` inside [`src/data/image-links.json`](src/data/image-links.json). This initial upload batch retains the exact order the client sent. New upload batches can be appended to the JSON and appear first. [Implementation 25](docs/implementation-25-wedding-moments.md) documents the workflow and publication safeguards.

## Dress pricing and details

Dress amounts are stored in [`src/data/products.json`](src/data/products.json) as whole-number ZAR values. **All twenty samples now have illustrative prices**, marked `priceStatus: illustrative`; these are placeholders for layout review, **not verified client quotes**. Categories are Mermaid, Ball Gown, Ruffled Dresses, Modern Tradition Dresses and 2 in 1 Dresses (four samples each). The floating detail card, category grids, online 22-page Digital Lookbook, and existing two-page downloadable sample PDF use this one source. The two-in-one photographs are styling references, not evidence that a particular gown physically converts. See [Implementation 27](docs/implementation-27-five-categories-demo-prices.md) for pricing, image sources and review steps; [Implementation 26](docs/implementation-26-dress-card-and-pricing.md) records the original card design.

## The Bridal Edit — 32-page downloadable PDF

Implementation 28 generates a luxury A4 portrait bridal PDF using the same twenty products and indicative ZAR prices as the website. The publication has a cover, three opening pages, five collection dividers, twenty one-dress-per-page presentations, a fitting contact page, photographer credits and a back cover.

The digital PDF is generated by **Playwright Chromium** during `npm run dev` and `npm run build`, with typography based on Cormorant Garamond and Montserrat. **Before the first run**, install the browser once:

```sh
npm ci
npm run setup
npm run check
npm run dev
```

High-resolution Pexels source images are fetched once into `.cache/redcarpert-lookbook/` and reused on later builds; they are not committed. The first build requires internet access to fetch uncached images and webfonts. A machine-readable resolution/DPI audit is written to `.generated/lookbook-image-audit.json` and flags photographs that cannot support a 300 DPI print layout at their current dimensions. The digital edition is not a printer-certified CMYK or PDF/X file; a print edition requires confirmation of printer specs and suitable photographs.

The current PDF is downloadable at `/digital-lookbook/Redcarpert-The-Bridal-Edit-YYYY.pdf` (year generated at build time). The previous `Redcarpert-Sample-Lookbook.pdf` URL is retained as a compatibility alias. Both contain the same 32-page book.

All dress prices and photographs are illustrative and not verified Redcarpert inventory or quotations. A low-resolution or missing photograph must be corrected before advertising print readiness.

## Validate and preview

```sh
npm run check
npm run preview -- --host 0.0.0.0 --port 4173
```

Run `npm run setup` to install Chromium, then `npm run test:browser` against the running preview. The production site is generated in `dist/` with standalone pages at the configured GitHub Pages base `/redcarpert-prototype/`.

## Hosting and safety

The repository GitHub Pages workflow validates pushes to `main`, but **does not deploy automatically**. Deployment requires an explicitly approved manual workflow dispatch on `main`; configure environment protection separately. The Implementation 11 verification workflow checks its implementation branch only and never deploys.

The fitting-enquiry interaction now opens a **live WhatsApp chat at +27 68 045 8811** only after a visitor reviews the prefilled message and selects Continue to WhatsApp; no message is sent automatically. Sample-detail messages name their selected demonstration dress. No booking backend, payments, confirmed inventory, studio address or opening hours have been configured. The owner reports having obtained permission to use the retained reference-derived design/theme assets; independent licensing documentation has not been inspected.

## Project layout

- `src/data/`: minimal presentation shells, catalogue samples and site metadata
- `src/lib/`: guarded content adapters, page generation helpers and PDF writer
- `src/client/`: native browser interactions, menu, scrolling and lookbook controls
- `src/components/` and `src/styles/`: styles required for the approved design
- `scripts/generate.ts`: renders all approved static routes and collects local assets
- `public/`: only production-relevant visuals, fonts, scripts and theme dependencies
- `tests/`: source, build and browser regression checks

Third-party theme effects remain temporarily to preserve the approved interactions. Implementation 12 refactored the supporting code without replacing these dependencies. The page-turn lookbook is Implementation 13. The catalogue retains its All Dresses / Mermaid / Ball Gown filters. Wedding Moments now uses an independent media gallery with photos and native video support; see [Implementation 25](docs/implementation-25-wedding-moments.md). See [asset credits](docs/asset-credits.md).

## Engineering notes

The static generator is organized as `scripts/generate.ts` (entry point), `scripts/lib/prepare-page.ts` (approved content/adapters), `scripts/lib/markup.ts` (safe HTML serialization), and `scripts/lib/assets.ts` (local dependency collection and copying). The single repository subpath configuration is `src/config/site.ts`. Browser features have independent enquiry and lookbook-reader modules under `src/client/`. Keep the existing fullpage and gallery theme dependencies until their behaviour can be replaced and independently regression-tested.

The `Verify static Redcarpert site` GitHub Actions workflow validates implementation branches and pull requests without deployment. Implementation 12 also checks generated HTML and PDF against the approved Implementation 11 baseline. See [the engineering hardening review](docs/implementation-12-hardening.md).
